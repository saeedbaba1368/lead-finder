# alembic/

Database migrations (Alembic). Configuration: `../alembic.ini` (CLI) and `env.py`.
The database URL comes from `APP_DATABASE_URL` (never from `alembic.ini`).

```bash
python -m app.cli db upgrade          # apply all migrations (same as: alembic upgrade head)
python -m app.cli db current          # show current/head; exit 1 if not at head
python -m app.cli db downgrade        # one step back ('base' = empty schema)
alembic revision --autogenerate -m "describe change"   # after editing models
alembic check                         # fails if models and migrations have drifted
alembic upgrade head --sql            # print SQL without touching a database
```

Rules
- Every model change ships with a migration. `tests/test_migrations.py::test_migrated_schema_matches_models_no_drift` fails otherwise.
- **Always review autogenerated migrations.** Autogenerate duplicates enum CHECK constraints and renders SQLite-specific server defaults; `0001` was hand-corrected (see `docs/database.md`).
- Use dialect-neutral defaults (`sa.func.now()`, `sa.true()`/`sa.false()`), not raw `sa.text('1')`.
- `env.py` uses `render_as_batch=True`, so SQLite can apply ALTER-style changes in later migrations.
- Migrations run on a plain engine with SQLite foreign-key enforcement off (required for batch table rebuilds).
